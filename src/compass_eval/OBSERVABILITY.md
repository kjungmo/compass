# Optional decision trace and offline opportunity scorer

The observability interface instruments decisions without itself changing knobs
or switching rules. The integrated branch also contains observer corrections,
safety fixes and separate opt-in controller paths; it is not identical to the
original archive. It is not a physical-evaluation implementation. The two core entry
points retain their signatures; additional overloads accept a caller-owned
DecisionTrace pointer. It is reset on every call, including safety returns.
No file I/O occurs in the core. A non-null trace copies candidate/state containers;
do not assume real-time safety without profiling and provisioning allocations.

Build and verify without ROS:

```sh
bash scripts/test_compass_observability.sh
```

Build in the existing ROS workspace using its normal colcon build. CMake adds
compass_trace and a BUILD_TESTING trace equivalence target. Historical successful
ROS Jazzy CI runs are recorded in [the checkpoint](../../docs/COMPASS_COMPLETION.md);
these are not local Gazebo or robot runs. Re-run CI for the final merged source.

The trace command takes: scenario seed progress_input output.jsonl.
Scenario names are the existing harness names. Output contains inputs, committed
and challenger classes, accumulator phases, actual threshold/rho used, safety and
reset flags, and post-step state. It does not claim measured physical clearance.

```sh
compass_trace clean_commit 0 0.35 blocked.jsonl
python3 scripts/evaluate_opportunities.py blocked.jsonl oracle.jsonl --end-time 10
```

Example oracle.jsonl (independently supplied, not generated from COMPASS J):

```json
{"id":"clean","onset":0,"confirmed":0.5,"deadline":3.5,"expiry":10,"target":[[7,0]],"hold":0.3,"lock_window":5}
```

The caller must ensure the oracle's target uses the trace's canonical relation
identity, or map both through evaluation-only ground truth before scoring. Raw
tracking IDs must not be mistaken for physical identity after an ID switch.

Outputs distinguish timely, late, missed, expired, safety interruption, insufficient
follow-up, competing failure, invalid log and already-target. A safety intervention
after an already missed deadline remains in the failure denominator. Required
hold is verified only by a later observed sample. Gaps invalidate the run rather
than silently making evidence continuous. Empty opportunity sets yield null recall.
Original deadlines, expiration and ground-truth warranted labels are evaluator
responsibilities. No censored response is imputed as zero or averaged as a success.

Limits: this scorer does not implement the geometric oracle, physical freezing,
motion observer, adaptive opportunity detection, theorem-bound eligibility, CI/
survival analysis, or the 480-run simulator. Those remain explicit follow-up work.
No scenario sampler was changed. Reproducibility still requires compiler/stdlib
and actual input data provenance. The canonical 1,500-row regression targets the
current corrected observer CSV generated by the existing libstdc++ harness;
it is not byte-identical to the original `9fe495a` archive. The 50,000-cycle
equivalence test compares trace/no-trace calls to the same current core, not old
and new policy versions. Record full source/config/input hashes, toolchain and
exact commands when collecting research data. Version 0.2.0 changes public
layouts/interfaces: rebuild all dependent binaries together.
