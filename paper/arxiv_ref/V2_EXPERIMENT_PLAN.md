# V2 experiment plan (post hoc, written before any new run)

Status: committed before any code for these experiments was run.
Origin: external review findings F1, F3, F4, F5 of 2026-11-14
(`ARIS_UPDATE_REVIEW_2026-11-14.md`). All experiments are added in v2 after
review. They are post hoc. They never replace an archived result: every
number in the v1 manuscript and in `NUMBERS.md` stays unchanged, and the
archived `ablation_raw.csv` is not rewritten.

Harness: the existing offline harness (`src/compass_eval`, actual
`DecisionCore`), the same 5 scripted scenarios, `dt = 0.05 s`, horizon 200
cycles, evaluation seeds 0..49 (50 per cell), the same switch-count
convention and the same decision-stream observer (`t_sfx`, eps = 0.2,
p* = 0.9, 0.30 s follow-up, right-censoring). New code lives in new files
(`harness_v2.hpp`, `src/v2_main.cpp`); `harness.hpp` and `main.cpp` are not
edited. All results are libstdc++ (g++) results. No libc++ toolchain is
available here, so no libc++ rerun is made for the new experiments.

## 0. Scripted target side per scenario (F4)

A "target side" is declared per scenario from the scenario script alone,
with one rule for all five: the target is the side that the scripted mean
advantage favours at the end of the horizon, except that a short scripted
spike does not count. The start side is R. Advantage > 0 favours L.

| scenario | scripted mean advantage | target side | minimum switches needed |
|---|---|---|---|
| near_tie | 0 (sigma 0.12) | none (no target) | 0 |
| transient_spike | -0.25, with +0.25 for cycles 80-99 | R (stay) | 0 |
| mid_reversal | ramp -0.25 to +0.25 | L (advantage is +0.25 at the end) | 1 |
| clean_commit | +0.40 | L | 1 |
| intermittent | +0.45 for 8 of 12 cycles, -0.05 for 4 (mean +0.28) | L | 1 |
| late_reversal (new, section 4) | +0.40, burst of -0.40, then +0.40 | L (stay) | 0 after the first switch (see section 4) |

Metric "correct final side" = final element of the decision stream equals the
target side. It is a property of the script, not an independent oracle, and
it says nothing about how fast the response was. The same rule gives
mid_reversal a target; if COMPASS misses it, that is reported as a miss.
The column is computed for all 6 archived policies and all new policies from
decision streams regenerated by the same code (the regenerated switch counts
of the 6 archived policies must equal `ablation_raw.csv` row by row; the
checker enforces this).

## 1. Experiment (a): new baselines (F1)

Two baselines are added, both in the spirit of the named works, neither a
reproduction of them.

- CW, previous-class consistency weight (spirit of de Groot 2024, SHINE):
  each cycle, score each class by `J - b * [class is the current class]`
  (bonus b for keeping the previous class) and commit to the argmin.
  Equivalent to an instantaneous switching margin `b` with no memory.
  Free parameter: `b`.
- LI, post-switch minimum dwell plus relative improvement (spirit of Li
  2026): switch to the best class if (time since the last switch >= T_min)
  and `(J_cur - J_best) >= r * J_cur`. No lock before the first switch. No
  accumulation. Free parameters: `T_min`, `r`.

Compared rows at native sigma (sigma 0.12 in near_tie, 0.03 elsewhere),
reported with exactly the metrics of the main table (switches, sign-change
rate, decision entropy, `t_sfx`, censoring) plus the final-side column:
the 6 archived policies, COMPASS lambda = 1, COMPASS with tuned `E_0`,
simple dwell with tuned `T_dwell`, CW with tuned `b`, LI with tuned
`(T_min, r)`.

## 2. Tuning procedure (identical for every rule, fixed now)

- Each rule has a fixed grid, listed below, in order of increasing
  switching resistance.
- Tuning data: scenarios near_tie, transient_spike, mid_reversal,
  clean_commit, intermittent at native sigma, tuning seeds 1000..1049.
  These seeds are disjoint from the evaluation seeds 0..49. late_reversal
  is not used for tuning.
- Tuning loss per run:
  `excess_switches + 3 * [final side != target side]`, where
  `excess_switches = max(0, switches - minimum switches needed)` from the
  table in section 0, and the second term is 0 in near_tie (no target).
  The weight 3 is a fixed choice made before any run.
- Selected parameter = the grid point with the lowest mean loss over all
  tuning runs (5 scenarios x 50 seeds). A tie is broken by the earlier grid
  point. The selected parameter is then applied unchanged to the evaluation
  seeds, to every sigma in section 3 (no retuning per sigma), and to
  section 4.
- The whole grid is also evaluated on the evaluation seeds and committed
  (aggregated per rule, parameter, scenario), so no grid point is hidden.
- Grids:
  - COMPASS: `E_0` in {0.10, 0.15, 0.20, 0.30, 0.40}; all other knobs at
    default (default `E_0` = 0.30 is the archived row). Tuning the
    simple-dwell and CW baselines but not COMPASS would be unfair, so
    COMPASS gets the same treatment.
  - Simple dwell: `T_dwell` in {0.2, 0.4, 0.6, 1.0, 1.5, 2.0} s (archived
    row = 0.6 s).
  - CW: `b` in {0.00, 0.05, 0.10, 0.15, 0.20, 0.30, 0.40} (b = 0 equals
    immediate argmin).
  - LI: `T_min` in {0.3, 0.6, 1.0, 2.0} s times `r` in {0.05, 0.10, 0.20,
    0.40}, 16 points, in row-major order (T_min outer).
- The tuned values may favour the baselines, because the tuning scenarios
  are the evaluation scenarios (different seeds). This holds for COMPASS
  too. It is reported as a limit.

## 3. Experiment (b): noise (F5)

- Report sigma per scenario in the text and table captions (0.12 for
  near_tie, 0.03 for the others).
- Uniform sigma sweep: sigma in {0.03, 0.06, 0.12, 0.20, 0.30}, the same
  sigma in all five scenarios (this replaces the native per-scenario value;
  uniform 0.03 therefore differs from native only in near_tie), 50 seeds per
  cell, same decision-stream observer and metrics. Policies: COMPASS
  (default), -hysteresis, -progress hardening, lambda = 1, tuned COMPASS
  (`E_0`), immediate argmin, simple dwell (0.6 s), tuned dwell, tuned CW,
  tuned LI. Rho input at 0.05 as in the archived scenarios.
- Quantity of interest: whether -hysteresis and -progress hardening still
  equal COMPASS as sigma grows, and where each rule starts to switch on
  noise. Primary readout: mean switches per encounter in near_tie and
  pooled over the five scenarios, and pooled correct final side.
- Reference quantity (for the text): the steady-state standard deviation of
  the leaky evidence accumulation per sigma is computed in closed form, as
  `sigma * dt / sqrt(1 - lambda^2)`, and compared with `E_0`. It is a
  reference, not a measurement.
- lambda = 1 (no leak) at default `E_0` and default knobs is added as a
  COMPASS variant in the native-sigma table and in the sweep.

## 4. Experiment (d): late spurious reversal (F3)

Feasible without new physics: it needs only a new scripted advantage and a
progress-rate input, both already parameters of the harness.

- Scenario `late_reversal`: advantage +0.40 for cycles 0..149 (COMPASS
  commits to L), then a scripted burst of advantage -0.40 (toward R) for
  `N_b` cycles starting at cycle 150, then +0.40 again until the end.
  Gaussian noise sigma 0.03. Progress input `v_lat = 0.15 m/s`. Because rho
  restarts at 0 on commit, rho is about 0.77 when the burst starts (a nearly
  complete maneuver; the observed value is recorded).
- Target side: L (stay). The burst is scripted as spurious by construction.
  Minimum switches needed: 1 (the first commit), so excess switches count
  every switch beyond the first.
- Headline `N_b` = 40 cycles (2.0 s). Complement: `N_b` in {20, 30, 40, 60}
  (all reported).
- Policies: COMPASS default, -progress hardening (`k_rho = 0`),
  -hysteresis, lambda = 1, immediate argmin, simple dwell (0.6 s), and the
  tuned dwell, CW and LI rows of section 2.
- Expectation written before running, from the noiseless recursion, and
  stated so the reader can discount it: with `k_rho = 1` the threshold near
  rho 0.8-0.9 is about 0.49-0.54 against `e_max_rev = 0.5`, so a reversal
  within 40 cycles is blocked; with `k_rho = 0` the threshold stays at 0.30
  and a burst of about 24 cycles is enough. The scenario is built to probe
  whether the mechanism can matter. A positive result shows only that it can
  matter in this script, not that the situation occurs in practice. A null
  result is reported as a null result.
- Metrics: switches, correct final side, number of runs that reverse during
  the burst, mean rho at burst start. Same observer columns are also written
  to the raw CSV.

## 5. Reporting rules

- All rows are reported, including those unfavourable to COMPASS. If a
  baseline matches or beats COMPASS on a metric, the text says so, and the
  claims in Sec. 4, Sec. 5 (limitations), the abstract, the introduction and
  the conclusion are narrowed to match. They are edited only as far as the
  new evidence requires.
- New material is labelled "added in v2 after review (post hoc)". Existing
  tables, figures and numbers are not changed.
- Every new number comes from committed code and committed raw CSVs under
  `src/compass_eval/results/v2_experiments/`, is recorded in `NUMBERS.md`,
  and is reproduced by `paper/arxiv_ref/tools/check_numbers.py` and
  `scripts/check_paper_numbers.py` (extended where needed).
- No physical simulation, no external planner, no human study is added.
  What is measured is still a decision-stream property of scripted inputs.
